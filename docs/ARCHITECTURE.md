# Architecture

## Rendering and hosting

Astro emits static HTML into `dist/`. The project does not use SSR, an adapter, a server, a database, or remote APIs. GitHub Actions builds and deploys the static files to GitHub Pages. Astro derives the repository base path during that build so links and assets work at the project URL.

## Content flow

`src/data/site.ts` contains site identity, navigation, capabilities, and working principles. `src/data/products.ts` is the source for the product portfolio and all product detail routes, including Vidoany and TokenSaver. `src/data/projects.ts` supplies the homepage's selected-project section for game, web, and original audio work. Each product status is a typed value and displayed from the same record.

`src/pages/products/[slug].astro` generates the product detail pages from the product list at build time. Shared metadata is created by `src/utils/seo.ts`; base-aware links are generated by `src/utils/paths.ts`; content validation helpers live in `src/utils/validation.ts`.

## Presentation

`src/layouts/BaseLayout.astro` owns page metadata and shared shell structure. Site navigation, footer, product cards, and icons are reusable components. `src/styles/global.css` defines the design tokens, responsive layouts, theme variables, and reduced-motion behavior. Tailwind CSS v4 is configured through `@tailwindcss/vite`; the design uses a small custom stylesheet to retain a clear visual system.

Theme defaults to the operating-system preference. A manual selection is saved under `zevqio-theme` in browser local storage; it is not sent to the site.

## Static outputs

- Astro Sitemap produces `sitemap-index.xml` and its page sitemap at build time.
- `src/pages/robots.txt.ts` generates a `robots.txt` file pointing to the sitemap at the current deployment URL.
- `public/site.webmanifest` uses relative paths so it works at the GitHub Pages project base path.
- `public/images/social-card.svg` is the editable preview artwork; its 1200×630 PNG is served to social crawlers.
- There are no analytics tags or third-party scripts.

## Quality checks

Vitest checks shared product, navigation, metadata, and validation data. Playwright checks routes, navigation, theme persistence, internal links, browser errors, keyboard entry, and horizontal overflow at the requested viewport sizes. GitHub Actions runs the same static checks and browser suite.
